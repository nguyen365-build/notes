How the queue runs

  1. Every hour, the driver reads the queue and picks the first question with no tutorial on disk. State is read from the notes\ folder itself, not from a saved cursor — so a failed run just retries next hour, and anything you write by hand is picked up as done automatically.
  2. That one question is handed to a brand-new Claude context running /my-math265-teach <QID>. Nothing carries over between questions.
  3. When the run finishes, the driver checks that notes\<QID> - <title>.md actually exists before recording it as done.
  4. One at a time, in bank order. A run still going when the next hour fires is left alone.
  5. When every question has a tutorial, the job turns itself off.

Usage-limit hits are not counted as failures — they simply retry next hour. A question that genuinely fails three times is skipped so the queue keeps moving.

One command left for you

The hourly job needs you to register it. The scripts are written and the queue logic is verified, but this session was not permitted to create a Scheduled Task or launch a background process. Run this once and the whole queue takes care of itself, including across reboots:

pwsh -NoProfile -ExecutionPolicy Bypass -File "C:\Users\mnguyen\Work\bin\math265-teach-register.ps1"

Until then, the queue is being driven from this Claude session instead — which works, but stops when the session closes.

Watch it

Get-Content C:\Users\mnguyen\Work\logs\math265-teach-ledger.log -Tail 20 -Wait

One line per hour: START, then OK with the file size, or FAIL / LIMIT / TIMEOUT with the reason. Pause anytime with Disable-ScheduledTask -TaskName 'ClaudeMath265Teach'.
